# laohan-laowai — 老外博主复刻数字人全流程

## 使命与合同

**用选定形象、专属音色与教育/文化内容制作数字人口播**。本skill是七阶段总控，本机/服务器CLI自动化，不走网页向导；确需基础素材时才按项目授权调用产品API。首个Deborah/海思博士案例是历史实例，当前形象/稿件/接受状态以各项目STATUS为准；用户当前指令和项目合同优先于本skill。

## 七阶段流程

### ① 博主选型与资料包

- 选型标准：教育者可信度 > 第一视角口播形态（talking head，非 vlog/skit/旁白）> 数据 > 类型差异
- 下载 5-8 条视频（laohan-xiazai：TikTok 用 yt-dlp 直下）+ info.json 元数据
- **口播形态逐帧验证**（抽帧+视觉模型确认正脸对镜头说话；抽帧落在无字幕间隙≠干净，必须多点验证）
- 选定博主不等于肖像/音色使用权、学历与亲历陈述已核实；不能以“改用虚构姓名”或“尚未商业化”宣称这些问题已解决。按项目合同核身份/来源/使用范围，不冒用真人身份、履历或接受记录。
- 换/加博主同步当前项目的素材追踪清单；素材数量与历史流量只作取样依据，实际可用性需本期核验。

### ② 声音模型（硬性前置，唯一方法=服务器微调）

**调用 skill `laohan-yinse`**：8-10 分钟素材 → pro6000-a 服务器 CosyVoice3 微调 → 模型回迁。视频生成前必须完成，否则声音违和。

### ③ 形象素材处理

- **分清入口限制**：竖版/短边≥720/时长≥8秒/≤30fps/MP4/<200MB是历史产品资产上传要求，不能当当前same-voice CLI的通用硬门；确需产品上传先读该产品现行合同。same-voice按当前工具核输入与几何，prepare转25fps并保持源画幅；原生清晰度、正脸/嘴部可见、字幕/遮挡与连续画面由本期视觉检查裁决，不靠升采样冒称细节达标。
- **不把产品上传门当same-voice适配验收**：576宽可通过本机prepare不证明TBDub实际效果；720宽也不证明全程无字/无遮挡。连续检查并先做已授权小样，不能拿几张无字截图保证整段干净。
- **字幕必须去除**（会被引擎复制进成片）：博主视频普遍带字幕 → 底部 crop 或换无字幕条；多点抽帧验证（首/中/尾/多段）
- 转码H.264、保存clean素材和剪辑边界/SHA；项目方法入口按项目INDEX读取，不恢复旧`docs/dh-production-guide.md`根路径。

### ④ 形象与声音资产（复用已有素材，不走产品注册）

- **形象素材：已有博主视频直接复用**（prepare 前多点抽帧验证全程同一正脸；开头 B-roll 插入画面必须掐掉——见⑤坑）
- **声音：laohan-yinse 微调模型整稿合成**（见②调用，24kHz PCM16 WAV 由 yinse 第 7 步产出）
- ~~产品 avatar-assets/voice-assets API 注册~~ **已淘汰**（2026-10-28）：那是产品网页向导链（零样本参考录音+29积分/次渲染），与本 skill 的 same-voice 路线互斥，且违反"声音不走零样本"红线。历史踩坑记录（MIME 显式 type / consentVersion=voice-reference-v2 / loudnorm 电平门禁）仅当未来确需产品链时参考。

### ⑤ 同声口型渲染（DH-ROUTE 路线④，2026-10-28 实战验证——唯一正确流程）

**方法真源：`~/Documents/laohanvideo/motion/mastery/DH-ROUTE.md` + `motion/tools/README-same-voice.md`（本节只是入口索引，冲突以真源为准）。**

不走的路（都验证过不是正路）：产品 lease/operations 报价链（29积分/次，网页向导已淘汰）、ispeech 图+音频（另一条产品链）、直控生产 worker。

```
① 最终 WAV：音色模型在 pro6000-a 合成整稿（laohan-yinse 流程）→ 24kHz 单声道 PCM16
② 形象素材：已有素材直接复用（无需产品订单）
③ Mac prepare：python3 motion/tools/same-voice-local.py prepare \
     --audio <24k.wav> --avatar <形象.mp4> --max-input-frames 180 --out <全新目录>
④ validate manifest → 上传 manifest/inputs/chunks/run-same-voice-remote.py 到
   pro6000-a:/root/autodl-tmp/laohan/motion-same-voice/<小写实验名>/
⑤ 预检（无 --run）→ 真跑：--run（total_timeout 3600s，单块 480s 上限）
⑥ Mac assemble：same-voice-local.py assemble → same-voice-candidate.mp4（原 WAV 主声）
```

**坑（全部实战踩过）**：
- ★形象素材开头可能是插入 B-roll（案例画面）——prepare 前多点抽帧验证全程同一正脸；mediapipe 丢脸 >10 帧直接 RuntimeError（chunk-001 判例：开头 5 秒小女孩 B-roll）
- ★生产活动保护触发即保存STOP现场。仅旧执行者及子进程组退出、检查点SHA/原基线/原范围/原截止均满足时，才按README显式恢复一次；生产基线改变不能用resume重置，更不能换目录无限重试同一失败块。
- 音频必须 24k 单声道 PCM16；180 帧分块上限（1080 宽输入 20GiB 内存保护）
- 隔离 runner SHA 必须匹配 `469d820e...`（冻结保护）
- 完成证据：assemble产物全帧数与清单相符，ffmpeg完整解码无错误（ffprobe只核元数据/帧数）；状态为候选待连续复看与Jeffrey接受。

**Motion模板包装、字幕与BGM**按本期已核交付范围执行。只交口型样片时不擅自扩为模板项目；需要完整Motion包装时再加载V4/PIPELINE及其生产门，不能把口型机械通过当模板或全片验收。

### ⑤.4 音频听审卡点（2026-10-28 补录）

⑤ 的 prepare/推理启动前，最终 WAV 必须已过 Jeffrey 整轨听审（听感不过→回 yinse 第 7 步调整重合成，不进推理浪费 GPU）。

### ⑤.5 成片统一加速（老方法既有项，2026-10-28 补录——别漏）

老韩系口播视频标配二次加速（motion 交付链 speed 参数）。成片级统一变速，口型同步不破坏、无需重跑推理：
```bash
ffmpeg -i <成片>.mp4 -filter_complex "[0:v]setpts=PTS/<S>[v];[0:a]atempo=<S>[a]" -map "[v]" -map "[a]" -c:v libx264 -crf 22 -c:a aac -b:a 128k <加速版>.mp4
# S 常用 1.05（微紧凑）/1.10（抖音节奏），音高不变；首期 Jeffrey 选档后每期固定
# ⚠️ 边界：成片级音画同因子加速≠音频变速——后者（单独 atempo WAV）会破坏口型同步，禁止；老方法"变速后受影响门重跑"指后者
```

加速版是新派生：记录倍率、输入与输出SHA；已有字幕/词锚同步换算到成片时间轴并复验首末词、口型与接缝。原WAV作为来源保留，不能把加速后音轨宣称与原WAV逐样本一致，也不直接沿用旧SRT。

## 完成证据（四道质量门，源自 Jeffrey 声音方法 v2.2，缺一不可）

① **听感门**：本期最终WAV绑定SHA且Jeffrey整轨听审通过，之后才做口型；② **唇音同步门**：连续播放复看口型、节奏与接缝；③ **机械门**：帧数/时钟一致、ffmpeg完整解码无错误、响度实测，ffprobe只负责元数据；④ **成片接受门**：Jeffrey看片明确接受。候选可在技术检查后交看片，发布批准另按项目合同处理，不把机械绿、候选交付或片子接受冒作已发布。

## 声音绑定与登记纪律（DH-ROUTE §五，2026-10-28 补录）

- 每期声音记录绑定完整 WAV 的路径/SHA/采样数/实测时长/听感接受记录；ASR、字幕、口型、后续混音**共用本期绑定**，新稿必有新 WAV
- **候选 ≠ 验收**：Jeffrey 授权先出样片时登记"本次授权+听审 PENDING"，不得登记为最终已验收；接受后才绑定真实接受记录

## 故障诊断顺序（源自声音方法 §4，补录）

- 口型跟不上/错位 → **先查音轨再重合成**：①核成片音轨=本次 WAV（时长/身份）②查时间轴 PTS 偏移（管线侧问题）③确属语速问题才回重合成（换沉稳参考+重过听感门）
- 音色不像 → 核风格路由 → 换相邻风格对比 → 仍不像报 Jeffrey（触发重训评估）
- GPU 准入/止损（与生产共卡）：合成前显存 >10G 才开工；合成卡 >5 分钟或生产桥报错 → 只杀**本次离线进程**（严禁动生产 bridge/服务），换时段重试
- **凭据零入档**：lease/token 只存在于运行时内存与既定凭证文件，不写进 skill/项目档案/git

## 失败路径

- 声音模型未建成 → 全流程停在②，不跳过训练直接渲染（零样本已被禁用）
- 形象素材字幕去不净/硬门槛不达 → 换素材条或重新选型，不降门槛上传
- 渲染链失败 → 按DH-ROUTE/README保留失败现场、原预算和检查点，执行其有限恢复条件；不得新增“再试三次”、换目录清零失败次数或退回网页/产品链绕路。
- 验收（深肤色还原/口型/音色）不过 → 回退候选形象名单（persona-candidates 排序），不硬发

## 服务器协作判例（2026-10-28 实战，pro6000-a）

- **网络/worker故障**须由具名生产维护任务处置；内容制作不得据历史判例重启worker或结束其它工作线进程。只读核实并让路，只能回收本任务已核身份的离线进程组。
- **resume基线变化**是保护条件，不能当成“脏了就换目录绕过”。保留原STOP/基线/次数；生产空闲且旧执行者已退后，确需继续时由root按README显式登记尚未计算范围的新有限阶段，不伪造旧阶段成功。
- `--expected-checkpoint-sha256`是batch-state.json文件本身SHA；内存增量或生产活动保护触发时不提高阈值、不盲重试、不清全局缓存。
- **分块断点**：18 块跑到 17 块被打断 → `--start-chunk 17 --end-chunk 18` 单补，assemble 时 `--additional-outputs` 合并

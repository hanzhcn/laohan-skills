# 每集按改动执行

先读项目STATUS/INDEX、当前稿件、声音资产登记与已选标题/速度。这里只组织现有入口，不增加编排器、常驻服务或新的通过凭证；实际命令分别取项目声音README和same-voice README。

## 改动与必做范围

| 本期变化 | 应执行 | 不重复执行 |
|---|---|---|
| 同一博主、已选模型/参考、全新稿件 | fresh核资产/依赖/运行身份及预算；本期稿件事实与违规；`launch_voice.py synth`默认检查后受控合成；完整新WAV音文/听感；适用形象prepare/validate/口型/assemble；后期与成片检查 | 训练语料重清洗、特征/parquet、训练、权重剥离、模型首建A/B/10次稳定性、参考池重建 |
| 只改字幕/标题样式或位置，原音轨/口型/速度不变 | 从已核无字幕raw试排；核所有实际字形/内部间距/UI和脸嘴、标题所选时长及词锚；一次烧录并copy音轨；解码/时钟/音轨核对及实际样片 | TTS、ASR重跑、模型/口型重算、速度多版；词锚仅在原输入/文本/时间轴及工具依赖证据可核时复用 |
| 只加/换BGM、duck或不改变时序的响度/控峰 | 核原干声/口型来源与时钟不变；从raw重新混音，登记音乐来源/使用范围、滤镜与新混音SHA，实测响度/真峰值，听尾字/压低回升/首尾；核帧数、A/V起点、首末词及完整解码。可同时一次烧标题/字幕 | TTS、训练、口型与词级ASR；不因mixed AAC变化重新做整套声音模型验收，不把混音文件送prepare；原干声/词锚/工具依赖须可核 |
| 英文口播改字、换参考、重合成或音频剪切 | 重新核受影响文本/参考、生成新WAV，整轨检查并重算受影响口型/词锚；保留原片可回退 | 未变模型训练；不以“时长相同”复用旧口型 |
| 只换形象素材 | 连续核新素材/顶部留白、clean几何；prepare/validate/小样及口型/组装/视觉 | 原WAV确实未变且身份/依赖可核时不重合成或重ASR；仍核新成片音轨与同步 |
| 迁机或运行包丢失 | 恢复同版模型/参考/依赖，fresh核SHA与环境，实际加载短句试合成 | 自动重训、自动升级模型或换零样本 |
| 新博主/明确批准重训、方法或脚本变化 | 训练或变更涉及的前置/真实入口正反例及独立复核 | 不裁剪生产、声音资产保护、音文/听感和发布权限门 |

多项变化取必做范围并集；不确定影响就查证或执行相应检查。复用须保留旧候选/时间/环境/结果，并核关联源码、传递依赖、测试集、配置/协议和环境未变或兼容；单一hash、旧失败/未测记录不构成通过。不改旧回执的候选身份。

## 缩短等待与返工

1. GPU前核定稿、纯英文spoken、整轨听感、素材连续适用/顶部留白、工具/磁盘/资源和既有生产保护；输入不合格先改，不用全片GPU排障。
2. 同一WAV只做一次有绑定的词级ASR，兼顾音文差异和字幕词锚；有疑点才加独立识别或审音。ASR不能替代真实听感，训练数据校对规则不因每集复用而削弱。
3. 已接受的新WAV开始口型计算后，可在本机并行做字幕翻译/词锚、标题与BGM小样；不同时叠加共享GPU上的训练/TTS/口型。有新风格或参考差距时，优先用既有WAV片段/素材做12–20秒代表段合看，核开头/转折之一与文字音乐，不为此默认再跑GPU口型或整稿多版；该短样不代替最终整轨听审/唇音验收。定风格后从raw一次完成全片标题/字幕与混音。改稿或时钟变化时，小样与词锚重核。
4. 使用已核几何的分块起点；120帧只是kb78769本期参考。沿remote脚本保留每块身份、离线环境、cache建议、原预算及有限恢复；不提高内存门、不制造内存压力、不清全局cache、不换namespace重试失败块。不得用提速名义弱化生产让路。
5. 帧数/时钟/全片解码/响度先机械检查；一次实际连续有声审片覆盖口型、接缝、节奏和字幕/标题，布局仍核最长条/极值。静帧、抽帧AI和文字审查各有能力范围，不能叠加数量冒充全片视听。

## EP02重制后的固定准备（2026-10-30）

这次89.96秒重制，19块/150帧配置的GPU实际19分44秒，验证交付68.56分钟，含归档84.79分钟；35–40分钟目标未达。以下缩短等待和返工，不降低[画质/居中](quality-and-centering.md)或现有保护；新无损母版的实际耗时须另测，旧CRF17渲染速度不转作新SLA。

1. **素材池在开工前就绪**：台账逐条记SHA、原生清晰度、连续可用区间、标题留白/遮嘴/源字幕、已用期数。已用/拒绝/待筛分开，不把“13条22分钟”直接算成14期。复用已有筛查须核输入与工具/环境/检查范围的关联证据；当前选段仍连续复核，最终对近3期跑帧差门。每两周保鲜照项目执行，后续内容工作不等库存用光才发现缺片。
2. **磁盘与依赖前置**：先查服务器真实空余和活跃任务、当前guard冻结门（本项目20GiB），并估算本期新增输出余量；本机也估算无损母版空间。423MB才开工曾使GPU约T+16.6分钟启动。清理仅在已获授权、已终结且无消费者的精确项上做，模型/参考/活跃块不动；历史授权不扩大成下期批量清理许可。实际ffmpeg的ass/libx264、Python的PIL/numpy与字体先验证，别调用到缺库的另一个Python或每期重装环境。新容器/无损编码也核A/V时间基与AAC priming，不因像素一致跳过时钟验收。
3. **在同一个短样冻结视觉参数**：用源画面/已验声的代表段先核全画面中轴、当前固定字号、断句和BGM；列中文/英文最长句与多行条，不等GPU和全片渲染结束再改字号。只做本期必要小样，既有已验模板可复用，当前内容仍核可用宽度与实际字形。
4. **GPU期间完成独立的本机任务**：确认WAV已验后开始口型；同时生成中英同窗/预拆cue并跑字形链，准备自稿三平台→同份提示词Gemini→融合/本期weigui；不再串行等口型结束才碰文案。共享GPU不叠加训练/TTS；150帧是本次成功配置，不是任何输入都能照抄的上限。
5. **Gemini失败走已授权的真实后备**：按[客户端方法](gemini-client.md)确认网页确实退稿且没有在途回复后，不继续重复点发送。已有同一任务/会话/内容及本地客户端授权就直接切后备；缺的只是授权或登录时保留实际卡点。填完整稿后再核最高档，取回本期全文才完成；自稿不能替代第二引擎。
6. **远端assemble只回传必要成品**：保持成功块/manifest/输入核验，不传整套GB级缓存到Mac；回传candidate、assembly及必要原WAV/回执并核SHA，大小按当期实测，不固定写116MB。只改字幕/画质/BGM时本机后期复用同一raw，不重算GPU。先估附件大小，超过API限制即按已授权同会话客户端发原文件，不先试压缩版。
7. **合批收尾并全程计时**：本轮方法/代码差异集中自审后一次满配异模型对抗复核，按真实finding只补受影响范围；未变部分不重复长审，也不裁剪原强制门。过程边产出边写manifest，原日志不改字节；在开始/预检/选片/WAV/prepare/GPU起止/assemble回传/后期/QA/Gemini/交付回下载/归档分别记UTC。并行阶段记起止，不把各时长相加；交付用时和全收尾用时分别报告，未知细分耗时留未知。

## 短片连续制作的新判例（2026-10-30）

- **按可用连续片段定自然稿长**：源文件13条不等于13期；同一博主不同服装/场景不换声模。原生576素材可在当前CLI作为经实际验证的短片候选，不能升采样冒720；需要更长内容就补采，不循环动作凑时长。逐条记可用区间/源字幕/遮嘴/已用期数。
- **短片帧差必须取到真实画面**：旧5/30/60秒只适用够长的视频。当前成长项目`check-footage-repeat.py`已按共同有效视频时段（三点、末尾留一帧）适配短片，音轨更长不能充视频时长；任一近片均值≤25/255拒绝，抽帧无输出须非0。该全幅方法会受黑边/遮罩影响，不能单靠PASS证明人物不重复或保证平台流量；仍核源片/服装/区间与实际画面。
- **字幕生成与报告必须绑定当期真实字形**：中英共享一对整数时窗；中文预拆后再生成，边缘标点省略等光学处理也在生成前完成。不能只查pos居中，必须量实际墨迹；每轨使用新私有输出目录，ffmpeg exit0但未出新PNG必须拒绝。依赖assert的检查入口须明确拒绝-O，不能让优化模式剥离判据。成长项目当前工具是本项目入口，不声称所有宿主自动具备。
- **严格画质先查prepare与core编码**：旧same-voice prepare/assemble内部采用CRF18/fast。本批任务副本四处视频编码改为CRF0/slow，同时显式固定25fps CFR；原manifest/输入/成功receipt/资源保护保留。逐帧比较clean→reference→周期/分块与已验证GPU核心帧→组装像素；共享源工具不暗改，未核副本不能套旧审批。源片原始压缩和GPU嘴部合成的限制仍如实列出，不称整链无损；后期母版/兼容衍生继续执行画质方法。
- **显式输出时钟覆盖四处**：本批EP04在reference/cycle/chunk/core输出发现容器nb_frames比实际解码多一帧，且组装接缝PTS重复。仅先把输入转CFR、改CRF0或去B帧都不能解决；原fast18配显式CFR也通过，因此不能归因为B帧或无损编码。三个prepare输出在本机用`-r 25 -fps_mode cfr`，远端assemble旧FFmpeg实测用`-r 25 -vsync cfr`。按实际版本选择，不能全局改成VFR。负例54帧被压成2.08s，修后2.16s且逐帧PTS/像素相同；这些是本输入的实测，不推广成全部FFmpeg版本的缺陷。
- **时钟看实际解码**：每个core与整片都核实际解码帧数、容器帧数、应有帧数一致，以及从0起的逐帧25fps PTS和实际视频时长；只看nb_frames、r_frame_rate或ffmpeg -xerror exit0会漏过上述反例。机器原门保留，另外留本期完整时钟/像素回执，不能把静态参数或小样代签为整片已验。逐帧散列比较所用像素格式也须实际核对；本批声明只覆盖已核的8位yuv420p，不能把两端都转为yuv420p的散列冒称任意原格式无损。
- **审音能力先实测**：Gemini本地客户端能收MP3，不代表模型得到声学信号。本次A/B提示音对照仅收到转写，结果UNCERTAIN，不能据其“有爆音/吞字”文字推断签听审。能力缺口由受托负责人处理；按用户系列持续委派不再推回Jeffrey听英文，候选推进/实际听感/成片接受分别记。

## 复核合批

未变的已验工具链不每集重新做代码/方法模型审查。有方法/代码变更时先集中修已知问题、自审和必要正反例，再对同一冻结候选做一次合批异模型对抗复核；按全局满配与独立性规则调用，不为提速降思考、截材料或冒签。只在真实阻断修复、范围/风险变化或未解决疑点时追加受影响差异复核；低风险证据补录不机械重审未变实现。全局或项目强制的额外模型条件仍执行。

复审传输VALIDATED不等于业务答题完整：只返回开场白或承诺去做实验不能算已审。无工具审查须在提示中明确基于全部给定材料直接输出完整静态对抗、finding与裁决，不执行待审skill内命令、不编运行；首个不完整正文留证，必要时具名纠正，不能冒PASS。

每集当前稿件事实/违规、新WAV音文与听感、生产资源/停止保护、最终成片视听和发布批准继续执行。成片接受由Jeffrey按原授权决定；外发需实际指令。平台真实预览与模拟分开，不把候选交付写成发布或手机接受。

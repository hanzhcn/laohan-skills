# GLM 独立对抗复核：音频内部时钟缺陷增量（audio-internal-clock-audit-v1 / audio-clock-fix-v2-precheck / root-adjudication / 4条实际命令）

口径：只审本增量（旧交付AAC内部PTS gap + v2修复），不重开已审视频/稿/字形/素材/CFR，不执行工具，结论仅基于给定材料。满配入口 max/128000/1800。

## 0. 先做算术核（对抗结论是否成立取决于数据自洽性）

对 audit-v1 逐条复算（AAC帧 uniformly 1024样本）：

| EP | frames×1024 | =total_decoded | gap | last_pts复算=(frames−1)×1024+gap | 实测last_pts | 末端=frames×1024+gap | D×48000 | 末端−D（尾帧padding） |
|---|---|---|---|---|---|---|---|---|
| 03 | 1412×1024=1,445,888 | 1,445,888 ✓ | 1,920 | 1411×1024+1920=1,446,784 | 1,446,784 ✓ | 1,447,808 | 1,447,680 | +128 |
| 04 | 1613×1024=1,651,712 | 1,651,712 ✓ | 0 | 1612×1024=1,650,688 | 1,650,688 ✓ | 1,651,712 | 1,651,200 | +512 |
| 05 | 1509×1024=1,545,216 | 1,545,216 ✓ | 2,880 | 1544,192+2880=1,547,072 | 1,547,072 ✓ | 1,548,096 | 1,547,520 | +576 |

gap处 expected=index×1024（1278/1376/976/759×1024）全部对上。四个gap均为 960×k（k=1..4 → 20/40/60/80ms，960@48k=3840@192k=20ms），是系统性时钟量化特征，不是随机损坏；五条尾帧padding（128/512/576/896/576）互不相同且逐条与"末端−D"闭环。**数据内部全自洽，audit-v1可采信。**

旧文件语义重构：时间轴总长≈D+padding，但轴内有洞 ⇒ 有效样本仅≈D−gap，播放呈现为洞处无声/失同步，且约gap量的尾部内容被挤出`-t D`被剪。新precheck：PCM恰为D×48000（1447680/1547520/1138560/915840 ✓）、gaps=[]、duration=D ✓。

## 1. 反例尝试（攻击→检验→结论）

**R1「仅首尾/总时长本可覆盖，无需逐帧」——攻击成立，恰证增量必要性。**
v1五条first_pts均0、容器/首尾均D，四条仍藏20–80ms内部洞。仅靠duration的门禁被本材料自身证伪。修复后若只回测duration同样不够——已由precheck的gaps=[]（逐帧PTS）补上。结论：攻击不推翻修复，反而坐实旧门禁缺陷。

**R2「gap是priming/padding假象」——不成立。**
priming体现在头部（首PTS/edit list/skip_samples），padding体现在尾帧；二者都是边缘效应。本gap位于流中部帧索引759/976/1278/1376，是解码序PTS相对累计期望的跳变，且各文件尾padding（128/512/576/896）与gap独立可分账闭环。假象说不成立。

**R3「用nb_samples合计断言有效时长」——作为方法学攻击部分成立，但root未犯此错。**
EP03合计1,445,888/48000=30.123s，若据此喊"内容短30ms"就是误读（差值=gap−padding混算）。正确判据=逐帧PTS连续+PCM精确计数+流/容器D，precheck正是这么给的。结论：方法学红线成立，现有证据未触线；裁决中固化为判据。

**R4「修复偷剪声音/改变语速」——不成立。**
四条命令：无atempo、无额外atrim（BGM atrim=D与原graph同参）；afade st=D−1.2全对（28.96/31.04/22.52/17.88）；aresample=48000与原`-ar48000`同目标同swr路径，仅显式化；asetpts=N/SR/TB只重写时间戳不动样本；PCM恰D×48000且amix duration=first以voice为首、voice≥D（否则PCM计数无法恰等）。内容窗与旧交付一致，只是时钟被拉直。

**R5「旧AAC二次编码」——不成立。**
四条命令输入只有voice-24k.wav+同曲BGM mp3，`-n`防覆盖，输出为新文件名（mix-clock-v2.m4a/normalized-clock-v2.wav），无任何旧AAC读入。

**R6「只改音频不能复用已审视觉」——条件性成立，转Finding。**
复用的合法前提是"新final的视频packet payload逐字节+PTS序列 == 已验final"。root仅对EP06给出了mux-payload-identities证据；EP03/05/07的同等身份链未在给定材料中出现。若无此链，先前视觉/字形/帧差签核在形式上不附着于新交付文件。（注意：四条展示命令只产m4a/wav，final重封装步骤的证据链因此不可省。）

**R7「新AAC套旧响度」——root已合规，但仍有缺口转Finding。**
precheck的input_i/input_tp等为本次新graph中loudnorm print_format=json实测（EP03 −18.70/−1.50等），未套旧值 ✓。但这是编码器前loudnorm自报：EP03 output_tp恰−1.50@目标−1.5，AAC编码后典型过冲0.2–0.5dB可能破线；EP07 output_tp −1.85高于其自身目标−2.2达0.35dB（大概率仍低于平台−1.5级上限，但须实测而非推断）。交付文件级I/TP终测未在材料中体现。

**R8「EP04也须重做求一致」——不成立。**
EP04用同一方法测得严格连续（last_pts=合计−1024分毫不差），是该方法的阴性对照，证明管线可产出无洞输出、缺陷定位在后混输出时钟而非内容损坏。对通过件重编码只引入新风险（新PTS/新响度/新封装变量），无收益。维持不重做正确。

**R9「官方文档⇒FFmpeg bug」——root限定正确。**
asetpts=N/SR/TB与loudnorm动态192k需显式输出采样率均为官方文档行为描述；gap的960×k量化与192k↔48k分块边界相符仅是机制假设。root把根因如实限定在"当前后混输出时钟"，未过度归因。采信。

**R10「数据伪造/身份冒用」——给定范围内未发现矛盾。**
全部算术闭环（见§0）；precheck样本数与D×48000精确相等；命令参数与叙述逐项吻合。不伪造媒体身份声明成立的前提是P1/P2身份探针落地（见下），材料中EP06已示范。

## 2. Findings（按严重度）

**F1（中，必补）交付final级内部PTS实测缺失/未示。** precheck的gaps=[]大概率测于mix m4a；root裁决#2对五条final只引duration审计。逐帧PTS必须直接打在五条交付final/master上，否则"全部五条内部PTS实测不可省"未闭环。
→ **P1**：对五条final跑与v1同schema逐帧PTS审计；判据：first解码PTS=0、gaps=[]、末端−D≤尾帧padding容差（以skip/end padding或edit list界定有效时长，禁用nb_samples合计断言）。

**F2（中，必补）EP03/05/07视频payload+PTS身份链缺失；EP04交付字节身份链缺失。**
→ **P2**：四条新final按EP06 mux-payload-identities.json同法验证视频逐包hash+PTS等于已验final，音频payload hash映射到new_mix_sha256；EP04 final整文件（或音视频payload）hash与v1审计登记值相等，使"04无gap"结论继续附着在交付字节上。

**F3（中，必补）交付文件响度/True Peak终测缺失。**
→ **P3**：对四条新交付（final音频）跑ebur128/loudnorm measure pass报I/TP/LRA；重点EP03（−1.50@编码前，编码后是否破−1.5）与EP07（−1.85）。按平台上限判定；超限仅重跑音频分支，不动其他域。

**F4（低，建议）PCM参照分支身份登记。** normalized-clock-v2.wav登记sha256+样本数（precheck已计样本数，补hash），作为"AAC与PCM同源于同一归一化序列"的可追溯锚。
→ **P4**（可选廉价）：新AAC解码PCM vs normalized-clock-v2.wav残差RMS/相关度（非bitexact），证明AAC分支承载同一序列。

**F5（记录，不阻断）听感门未签。** 时钟/样本/时长证据不能代签主观听感、连续语声感知、用户与平台接受（root已明示未代签，维持）。

**F6（记录）gap量化规律（960×k）与192k↔48k边界相符**——仅作观察写入报告，不升级为根因结论。

## 3. 业务裁决

**裁决：本音频内部时钟增量——通过（APPROVE），附P1/P2/P3三项必补交付级探针作为放行闭环条件（属验证性收尾，非返工）；P4建议、F5另门。**

依据：
1. **缺陷为真且旧门禁不足**：五条首尾/容器D全部正确下，03/05/06/07藏40/60/80/20ms内部PTS洞，数据逐项算术自洽；仅duration的门禁被证伪。
2. **修复正确且最小**：从原PCM+同曲BGM重跑原混音图（参数逐项与原一致），仅在loudnorm后显式aresample=48000+asetpts=N/SR/TB（均为官方文档行为），PCM/AAC同源分叉、双输出−t D；无变速、无偷剪、无旧AAC二次编码；新PCM恰D×48000、AAC首解码PTS=0且逐帧连续、流/容器D。priming/尾padding与有效时长已按正确方法区分。
3. **范围纪律**：不动WAV/GPU/video/字幕；EP04作无gap阴性对照不重做；根因如实限定"当前后混输出时钟"，不归因FFmpeg bug；新AAC响度已重新实测未套旧值。
4. **复用有条件成立**：视觉/字形/帧差等已审结论仅在P2身份链（视频payload+PTS逐包相等）成立时附着于新final——EP06已示范，03/05/07照做即闭。

**禁改项**：不得重开视频/稿/字形/素材/CFR；不得重编码EP04；不得复用旧AAC或旧响度数值；不得以nb_samples合计替代PTS连续性判据。

**未签署项**：主观听感、连续语声感知、用户/平台接受（F5，另行人审门，本复核不代签）。

**证伪条件（任一触发即回滚本增量）**：P1在任何一条final再现gap；P2视频payload/PTS不等或EP04字节链断裂；P3交付TP破平台上限。

# 教程型口播稿写作规范（jiaochengstyle）

> 版本: v1.4 | 2026-10-24 | 适用：老韩AI 教程型视频
> 用途：从真实资料提炼简单、可跟做的操作，不以风格完整代替用户学会
> 配合项目六步法“教学动作主线”和creation-contract执行；本风格无需额外加载style.md。

---

## 整体结构：操作主线优先

品牌开场→本次能做成什么/必要准备→连续编号操作→核对结果→收尾。先把用户从起点带到结果，再按需要补原理、场景与观点。

下面的开头、衔接、正文、品牌、结尾是表达工具，不是缺一不可的五层铺垫。误区、比喻、分享、收藏或系列介绍没有帮助就不加；不为套模板推迟第一步。步骤数量按任务，不固定三步。

---

## 第1层：开头层

**位置**：全文第一段
**功能**：5秒内抓住注意力 + 降低跳出 + 拉互动数据

第一句默认使用：

> 嘿，你有没有这种感觉，

题目钩子接在品牌开场之后。只有Jeffrey本次明确指定其它开场才例外并记录真实依据；模型自认更强不能删除品牌习惯。机械锚点QA按共同合同执行，不为代理时长删必要条件。

随后尽快说清本次具体结果和必要准备；以下成分按需使用，不要求全有：

| 成分 | 写法 | 作用 | 示例 |
|------|------|------|------|
| 痛点钩子 | 用2-3个问句浓缩目标受众的痛点 | 情绪共鸣 | "还在一个一个平台翻热点？还在百度搜问题翻三页全是广告？" |
| 全覆盖声明 | 一句话说"不管你是X还是Y都适合" | 降低跳出 | "从入门到进阶，不管你是纯小白还是老手都有适合你的" |
| 行动号召 | 有真实保存价值时再提醒收藏 | 便于以后跟做 | 可放合适位置，不要求每篇或开头必有 |

**规则**：
- 禁止绕弯子。题目钩子接在品牌开场后，尽快进入具体任务
- 禁止先自我介绍再切入主题。身份信息放在结尾层
- 适用条件按真实设备/版本/任务说明，不为了全覆盖写“所有人都适合”
- 如有真实分享预告，也在此层末尾说出："还会把XX分享给你"

---

## 第2层：衔接段

**位置**：开头层之后、正文第一段之前
**功能**：用认知颠覆稳住注意力，从情绪（钩子）过渡到理性（正文）

只有误解会妨碍操作时才用下面两项；可以把必要解释直接放到对应步骤：

| 成分 | 写法 | 作用 |
|------|------|------|
| 大众误解 | "先说一个很多人没搞明白的事" 或 "很多人以为X，其实不是" | 暗示"你之前的理解是错的"，触发好奇 |
| 反常识正解 | 给出跟大众认知相反的正确答案 | 让观众获得"顿悟感"，建立信任 |

**规则**：
- 不强造大众误解或反常识，不为铺垫延迟动手
- 解释必须帮助当前任务；术语用一句人话解释到能操作即可

---

## 第3层：正文层

**位置**：衔接段之后、结尾层之前
**功能**：让观众按步骤做成任务；一段可承担动作、必要解释或承接，不为分段制造新观点

### 编号动作链

- 用连续的`1、2、3……`，口播“第一步、第二步……”。每步写清入口/对象、动作、必要输入，以及看到什么可继续；一个孤立动作不等于整个教程完成。
- 分清用户动作与AI代办。写明在哪个工具交哪个项目/文件、说什么需求、本人点什么授权、如何确认结果；只有“交给AI、配置一下”不合格。
- 步骤按真实依赖排列，上一结果交给下一动作。长提示词/命令另存可复制资源，正文仍教用户放哪里、如何用及如何填自己的信息。
- 用本地命令处理下载文件时，说清先进入哪个文件夹或使用实际完整路径，不能只给裸文件名让用户猜当前目录；未生成的资源不说“已备好”。
- 缺来源或关键操作就先补材料；不编造步骤、通用成功保证或亲测。机型/版本条件在对应步骤简短说明，避免整篇只剩边界提醒。

### 正文六要素（按需检查，不凑齐）

六要素是可选检查视角，不能代替编号动作链，不要求每段或每篇凑齐。真实动作推进、核对结果与必要承接都有作用，不能因没有新观点删除。

| # | 要素 | 定义 | 合格标准 |
|---|------|------|---------|
| 1 | 推荐 | 明确告诉观众推荐什么 | 观众读完能说出"他推荐的是X" |
| 2 | 痛点 | 用户在受什么苦 | 必须是具体场景。"五个平台看下来半小时没了"✓ "效率不高"✗ |
| 3 | 误区 | 用户常见的错误认知 | 格式："很多人以为X，其实不是" 或 "你可能觉得X，其实不是" |
| 4 | 如何用 | 具体操作步骤 | 观众听完能直接动手；命令、地址或模板若需复制，独立生成完整观众资源 |
| 5 | 好处 | 用了能得到什么 | 必须具体可感知。"十分钟全部看完"✓ "提升效率"✗ |
| 6 | 理由 | 凭什么这么推荐 | 必须有依据。"我自己实测下来" 或 "十几个平台接口都封装好了" |

### 步骤之间的自然承接

- 用完成状态、对象或因果把相邻步骤串起来；直接相接也要让观众知道上一结果怎样用于下一步，不强制每次插同一句套话
- 例如“电脑已经连上电视了，接下来让AI检查机型和现有桌面”。“先、然后、接下来、最后”和必要的对象重复可以自然使用
- 编号是路标，承接句讲关系；只有“下面第二点”或突然换对象，仍须改顺

### 正文质量标准

| 标准 | 定义 | 反面案例 |
|------|------|---------|
| 干货 | 必要动作、输入、结果和承接完整，用户能跟做 | 讲了原理和好处，仍不知道从哪开始 |
| 丝滑 | 段间过渡有因果关系，不生硬 | "接下来讲第二个"✗ vs "但这个只管拿数据，看下一个"✓ |
| 节奏 | 快慢交替。痛点/误区快，好处/理由慢 | 全程一个语速 |

### 口播、导演锚点与观众资源分离

`01-口播稿.md`正文只写Jeffrey真正说出口的话，不插入`[B-Roll]`、`[字幕]`、`[画面]`、镜头、转场、特效或Remotion执行提示。教程中出现对比、过程、数据或步骤时，在`创作决策.json.visual_anchors`只记录“观众需要看懂什么”和适合的抽象表达类型；具体视觉方向、动画技术、时长、位置与人物避让由后续导演和实拍对齐决定。

命令、地址、模板、清单或提示词如果承诺给观众复制，必须独立生成`12-发布/观众资源/<资源名>.md`：

- 全部字段使用完整、可直接复制的推荐值，不留`[填写]`、`[粘贴]`、TODO、TBD或空字段；
- 示例可以与观众实际项目不同，但必须明确写“这是推荐起点，请按自己的项目判断并修改”；
- `audience_resource_contract`绑定资源路径、SHA和四平台交付方式；
- 资源本体不进入口播、TTS、内容单位、段落审计或导演合同。

不设目标字数和分钟数。热点或单点技巧内容短时保持精干；需要更长只能补新的机制、案例、反例、操作或边界，不能重复好处、结论或背景。

## 第4层：品牌层

**位置**：嵌在正文层中，位置灵活
**功能**：转粉 + 记忆点

### 真实分享（有记录且帮助操作时使用）

“老韩亲测/踩坑”要与真实记录一致，助手查文档不能变成Jeffrey亲历；缺记录不强造分享。观点可直接说，测试不确定先补验证，不因此删掉已有操作资料。

| 属性 | 说明 |
|------|------|
| 定义 | "我怎么用的" — 创作者的真实使用场景 |
| 作用 | 建立信任 → 转粉 |
| 必须包含 | 具体场景 + 具体动作 + 具体结果 |
| 正确 | "老韩每天早上做选题，用opencli把知乎热榜抓一遍，十分钟全部看完" |
| 错误 | "我觉得这个工具很好用"（无场景无动作无结果）|
| 铺垫 | 开头层可预告"还会把XX分享给你"，正文中兑现 |

### 比喻/类比（能帮助理解才使用）

| 属性 | 说明 |
|------|------|
| 定义 | 用生活化场景让抽象概念秒懂 |
| 作用 | 降低理解门槛 + 创造记忆点 |
| 必须 | 观众日常能接触的东西，不能是另一个抽象概念 |
| 正确 | "Claude Code是框架，Claude是模型，就像手机和SIM卡" |
| 错误 | "它像一个中间件，把上下层解耦"（用术语解释术语）|

### 真实分享 vs 素材提供的区别

- 真实分享 = "我怎么用的" → 驱动信任 → 转粉
- 素材提供 = "我给你准备好了" → 驱动依赖 → 拉收藏
- 经常成对出现：先分享用法，再说"东西给你准备好了"

## 第5层：结尾层

**位置**：全文最后
**功能**：总结 + 拉收藏 + 固定收尾

优先确认做成了什么，并给出需要的下一步和固定ending；下面其余成分按真实内容选择，不固定四件套：

| # | 成分 | 写法 |
|---|------|------|
| 1 | 一句话总结 | 浓缩成行动指令，不复述内容 |
| 2 | 素材提供 | "XX我全准备好了"（呼应开头预告） |
| 3 | 系列标识 | "这是「老韩AI」的第X期" |
| 4 | 固定ending | "我是老韩，咱们下期见。" |

**规则**：
- 禁止重复正文内容
- 素材提供必须对应一份②已完整落盘并绑定SHA的观众资源；MANUAL发布时可由Jeffrey按冻结交付方式放入介绍或置顶评论，不能只在口播里承诺

## 主推标题与视频介绍方法

教程型主推标题按“工具或场景 + 动作 + 具体结果”生成：

1. 先确定观众能完成的唯一动作，不能只写“分享一个工具”。
2. 选正文已经证明的结果，优先时间、数量、步骤、成本或前后对比。
3. 工具名是明确搜索词时放进标题；陌生产品名不能替代观众能搜到的任务词。
4. 内部生成3个候选，按“搜索词明确、动作具体、结果可兑现、念着顺口”选出唯一主推标题。
5. 禁止用正文没有演示或没有事实边界的“翻倍、一键、永久、全自动”等承诺。

视频介绍按 `观众问题 → 本期教什么 → 实测或步骤证据 → 观众下一步 → 单一互动问题` 写，不复述整篇教程。介绍末尾附题材、工具、教程类型和品牌标签，每次必须原样包含抖音活动标签 `#AI新星计划`。

最终稿在口播正文之后固定追加：

```markdown
## 抖音发布信息

### 主推标题
[唯一主推标题]

### 视频介绍
[视频介绍正文]

#本题标签 #AI新星计划
```

该区域不口播，不计入TTS、正文段落或有效口播字数。

## 自检清单（输出前必须逐项确认）

### 结构完整性

- [ ] 开场后尽快明确具体结果和必要准备，未硬塞全覆盖、误区或CTA铺垫
- [ ] 从起点到结果的完整操作链，使用连续1、2、3……并口播步骤；每步对象/必要输入/核对结果清楚
- [ ] 前一步结果与后一步动作自然衔接，新手不需自行猜缺失环节
- [ ] 用户与AI各做什么清楚，长资源另存但关键操作仍在正文
- [ ] 真实分享和比喻只在有据、有帮助时使用，未为风格凑次数
- [ ] 结尾确认结果与下一步，保留固定ending；资源或系列信息真实存在才提

### 内容质量

- [ ] 无重复：同一信息不出现两次
- [ ] 如使用痛点：具体可感知；不为补痛点拖延第一步
- [ ] 误区/原理只在影响操作时解释，不强制反常识句式
- [ ] 好处可感知：观众能感知到具体收益
- [ ] 理由有依据：有实测/事实支撑
- [ ] 主推标题：内部3个候选，最终只留1个，搜索词、动作和结果都由正文兑现
- [ ] 视频介绍：观众问题→本期教什么→实测或步骤证据→下一步→1个互动问题
- [ ] 标签：必须包含`#AI新星计划`
- [ ] 正文纯净：没有B-Roll、字幕、镜头、转场、特效或Remotion执行提示
- [ ] 观众资源：凡正文承诺的模板、清单、提示词或命令均已独立完整落盘，无占位符，并绑定四平台交付方式

### 数据准确

- [ ] 工具名称拼写正确
- [ ] Star数/版本号等数据与实际一致
- [ ] 安装命令可执行
- [ ] GitHub地址有效

## 语言质量规则

### 词语检查线索（按语境与Sepia诊断，不自动判失败）

意味着什么、本质上、换句话说、不可否认、综上所述、总的来说、值得注意的是、不难发现、作为一个、让我们、不妨、试想一下、值得一提的是、赋能、抓手、赛道（比喻除外）、壁垒、痛点

### AI味检查线索（不以命中率代替跟做能力）

- 体制化开头：不可否认/众所周知/在当今的时代/随着...的发展
- 空心强化：真正地/不得不说/坦率地说
- 三连排比：连续 3+ 相同句式
- 冒号堆砌：一段内 >3 个「：」后接列表
- 过度总结：由此可见/这充分说明/这告诉我们
- 假设复数："我们都知道"/"每个人都会"（应用"你"单数）
- AI填充：值得注意的是/毋庸置疑/显而易见
- 空洞大词：至关重要/开创性的

### 标点

服从口播呼吸和原意；编号不删，命令/地址/可复制资源的标点不得为风格改写。

### 结构检查

避免空泛铺垫。教学编号和“先/然后/接下来/最后”按动作关系使用，不按列表条数或连接词判坏。

### 语感规则

- 句长服从意思和呼吸；关键动作、输入和条件不可为短句比例删除
- 解释需要时说完整，不规定短句/长句交替、反问次数或间隔

### 废话感（按真实作者习惯自然保留，不设数量配额）

单字结巴"能能"、夸张重复"等等等等等"、三连"太太太"、情绪"哎呦喂""哎"、方言"杠杠滴"、命令"你听我的"、自问自答、自嘲、数字犹豫"没有3万有2万"、无奈口头禅"这一天天的"、签名互动"是不是有点意思"、连续反问"是不是...是不是..."、确认词"对吧""你说呢"、程度词"真的""巨"、口语解释"就是..."

永久禁用「这个可有点意思」「可有点意思」。Jeffrey不会这样说；需要互动判断时用「是不是有点意思」，需要无奈收口时用「这一天天的」。

这些是人味设备，不是内容单位。内容语义去重时保留它们，但不能靠增加人味设备次数追目标时长。

### 用词规则

- 自称：主称"我"和"老韩"，号召用"咱"
- 称呼听众：保留默认签名开场，中间按语气用「你」「你们」「大家」
- 动作词：丢给/喂给/塞给/跑通
- 解释词：「就是」是最强的口语解释词

### 转场句式

**推荐**（交替使用，不连续用同一种）：
- 强互动：「你可能会问」「你猜怎么着」「你想想看」「是不是有点意思」
- 因果收束：「所以说」「也就是说」「你看」
- 关联跳跃：「说到这个」（每篇最多2次）
- 节奏切换：「好了不绕了」「先说结论」
- 独立信息可直接换段；依赖前一步结果的操作须有自然承接，不突然换对象

避免只念大纲的空转，如“接下来我们聊聊另一个重要方面”。直接说前一步做成了什么、下一步做什么；不禁止“首先/然后/接下来/最后”。

### 二创脱敏

- 论据可按本题重排；操作先后必须服从真实依赖，不能为错位或去同源打乱步骤
- 比喻/类比：原稿好比喻可保留标注引用，替换必须 ≥ 原版冲击力
- 老韩增量至少1处完整判断，不硬凑数量：每处提供新信息/新视角/新类比/新领域连接，禁空泛总结
- 论证路径换血：事实数字保持原值，可换论证顺序
- 核心原话可标注引用保留，每篇 ≤2 处，不伪装成自己的
- 底线：不整段搬运（>3句连续雷同）

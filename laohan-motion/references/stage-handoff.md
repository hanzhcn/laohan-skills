# 阶段交接：用新会话接收完整产物

本页只定义laohan-motion的分会话操作；创作、制作、授权和验收仍认现行真源。不创建第二份STATUS或自动质量状态机。

## 谁做什么

| 会话 | 工作与结束边界 | 交给下一阶段 |
|---|---|---|
| 主会话 | 绑定任务、派发监督、按原合同裁决定题；root唯一写融合定稿并审校、锁定，再派发制作；正式STATUS及Git集成。不连续兼任三个阶段的独立原稿作者 | 明确授权终点、完整显示稿/发音稿/观众文字、双稿融合证据及未决问题 |
| 选题新会话 | xuanti共同选题；LOCAL/Gemini各自排序，原selection/material独立前置照常 | 双方排序/理由、完整研究/源文/素材、事实边界和真实能力需求交主会话；不预定下一阶段构图 |
| 写作新会话 | chuangzuo/Sepia；LOCAL与Gemini各出全部文字，只交完整原稿、来源、双稿证据和未决项，不自行锁定或改写最终稿 | 原稿与不可删改限定交主会话；主会话融合锁定后才向制作交接，不把废弃稿注入制作prompt |
| 制作新会话 | 接锁定稿与授权；连续完成声音/人物、模板学习、导演、A/pilot、整片与交付 | 当前候选及完整回执；规划/结果异模型审核仍独立 |

用户仅要单阶段时只开所需会话；已有锁稿不补造选题/写作窗口。阶段内恢复可续原会话；跨到下一阶段重新创建，不用resume继承上一阶段聊天。长制作出现上下文混杂或连续返工时，按V4带检查点交新的专注制作会话。双稿互不泄露只约束同阶段独立原稿；已共同定案的选题和事实必须传递。

阶段派发由主会话负责；已经通过真实接收核对的阶段会话直接执行自己的阶段，不因再次读取本skill而递归新建同阶段会话。阶段完成回报主会话，由主会话派发下一阶段；技术子任务仍按现有依赖和写权纪律处理。

## 实际派发与接收

1. 按DEV_RULES§10先落实监督，再用Paseo的`list_profiles`/必要的provider查询核真实入口；不使用guiji。将选定provider/model与合法最高思考档、权限在`create_agent.settings`显式传入，开启完成通知；不运行中改档。主会话自动创建，无需Jeffrey复制提示词。其它宿主只能用已验证的不继承对话的等价新会话入口，并如实记渠道。
2. 在既有研究/工程qa中保存本阶段任务包，含下列最小交接内容，直接作为`initialPrompt`或明确读取入口。新agent没有主会话聊天历史；不使用全历史fork。子任务文件归属单一，正式STATUS仅root写，并行改代码按全局独立worktree，不能共享index。
3. 留实际`agentId`、provider/model、settings、发出任务包路径/SHA和创建回执；接收者先读真源，回传任务/阶段、自己的会话身份、输入路径/SHA、已读适用规则、授权终点、缺项及历史结论暴露范围。root核创建身份与回执对应后续接，不能只凭“已收到”或自填sessionId认定成功。
4. 缺失/错SHA/错任务/超出授权的输入停对应依赖，回发给原阶段修正；不让接收者猜版本或偷偷改稿。工具不可用、未知会话身份或仍继承旧对话时标`FRESH_STAGE_UNVERIFIED`，不把文档分段当已隔离。完成回执与超限处置、进程终态、临时监督回收均按§10。

## 最小交接内容

- 任务ID、阶段、项目绝对路径/分支/候选、唯一writer、输出目录、允许/禁止动作与授权出处；预计工作和调用预算、监督与失败后责任人。
- 全局/项目必读入口与当前阶段方法；版本以本次实际读取为准，另一模型读过不代本人阅读。
- 上游完整冻结产物、必要源文/素材/证据与路径SHA；用户目标、观众理解任务、画幅/事实限定、反馈中的具体问题、尚未完成项。完整文件必须可达，摘要只用于定位。
- 下一条真实入口与完成条件。制作侧拿最终稿及双稿证据索引，不默认重读所有草稿；遇出处/融合疑问再回原件核，不隐藏反例或用户否决。
- 不注入完整聊天、旧作者“已很好/已批准”、失败方案的预设修法、旧模板偏好或无关历史；已认可且要求保留的效果、实际技术故障与防护仍须传递。必读STATUS、自动记忆可能暴露历史，必须承认，不能称完全盲审。

验证分开记录：真实新会话创建/接收探针只证明已测宿主的交接路径；完整阶段执行、下期出片耗时和最终质量另以真实产物验收。测试任务可用nonce、文件SHA和适用规则事实核对接收，不把测试当新一期制作或替旧片补历史会话。

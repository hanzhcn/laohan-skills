# 依赖、局部恢复与计时

这是laohan-motion的调度参考，不是新生产方法或自动调度器。每个节点仍执行主入口指向的现行真源；阶段/授权/质量判定以项目合同和真实回执为准。

## 开始时一次整理

在STATUS的本期任务卡写清任务ID、唯一writer、准确研究/稿件/工程目录、目标/画幅、授权终点、当前产物与唯一下一动作。任务清单沿SKILL的①—⑦记录，失败原因和实际命令在既有qa留证；不用另一份任务表争夺状态真源。

昂贵生产前把可避免的失败提前发现：本人原片实看、禁用标记与来源SHA；Gemini实际可达及完整取稿；现有TTS/口型环境、声学解释器、包/helper身份与匹配缓存、磁盘/共享GPU活动；核本期原有故障和已验修法。检查只做当前步骤需要的真实轻量调用，不借“预检”下产品订单、重装全环境或跑全片。可用性随时间变化，正式运行仍执行原有preflight。

## 无依赖时并行，有依赖时汇合

| 当前主线 | 可同时做 | 必须等待 |
|---|---|---|
| 研究/共同选题 | 只读本人原片筛选、模板catalog轻刷新、工具和存储检查 | 题未共同定案不能锁稿；素材/声音生产依本期授权及内容前置 |
| 独立双稿 | LOCAL写自己稿时等待Gemini独立完整稿；核事实来源、候选模板公开能力 | 双原稿完整后才融合，不把本地结构交给Gemini |
| 融合稿冻结、串行TTS | 已融合封面/平台材料整理，候选模板契约/缓存doctor/素材核验 | 最终WAV生成前不启动该稿口型或声学对齐 |
| 最终WAV冻结、口型GPU运行 | 在资源允许时本地对齐该WAV、字幕准备、无依赖模板准备、已融合封面生成 | 不消费未完成口型；完整人物/词源等齐后才封存正式director/direct |
| 已有真实素材、导演/参数准备 | 同一writer按依赖完成本期能力样段与风险样段；封面可在独立目录继续 | 正式plan/preview/样段/请求齐全并独立批准后才render |
| 全片渲染 | 整理已融合文案、封面、原稿和交付清单草稿 | 最终视频SHA未知时不签最终复核/delivery，不先发包 |

“模板准备”仅指catalog、候选能力/分支资料、缓存doctor与素材核验。真实声学source_record和完整人物等未就绪时，不运行正式direct，不伪造时轴/人物占位签名。缓存若不匹配，按PIPELINE新路径setup；不得覆盖在途缓存。

资源互斥必须守：v3-05现有合成入口的共享文本串行写；同一GPU任务按现有准入调度；同一record、instance、cache不并发写，生产日志/STATUS单writer。CPU/内存/磁盘不足时收窄并行，不以并发数量衡量效率。分块由现有runner和resume处理，不能临时多开同一任务。只读子agent有明确收益且符合DEV_RULES§10时才委派，监督/完整任务包/回收齐备；不为每个命令开一个agent。

## Gemini与复核怎样合批

默认安排两个内容批：①中立候选包的独立排序；②共同定题后已知全部文案的独立完整稿。不是硬上限，实际原答截断或后加画面文字要补对应项。题目、标签、封面和画面讲解文字全部在范围内；首次采用旧作/模板措辞也不能漏掉。两个批按双引擎真源用干净上下文，不透露对方当阶段稿或排序。

融合立即按四平台现行规格检查实际长度、标签、互异和事实对应；不把字数自报当合格。已有本期融合的同文同SHA用于三封面排版等，只引用原证据；内容增改按双引擎方法补受影响项。Gemini失败修真实故障或用已授权替代通道，仍失败记BLOCKED_GEMINI，只推进不依赖它的工作。

制作独立审在规划样段终点和全片结果终点进行，审前把当前真实输入、动态媒体和完整目标一次给齐，减少补材料往返；不逐工具另开复审。选题/材料的现行独立前置不取消，可按原合同同批完成；因此“两个制作复核点”不等于从选题起全链只有两次模型调用。返修改变绑定时仍按PIPELINE重走相应终点，不以旧批准免复核。

## 变更先定影响，再重跑

| 实际变化/失败 | 处理范围 |
|---|---|
| 只改未入视频的发布标题/标签/介绍 | 按双稿规则补受影响文字、重核发布物料与交付清单；原视频/WAV/口型字节未变不重生成 |
| 画面文字、字幕断句/样式或模板参数改变 | 核文案融合及真实词界，按PIPELINE重plan/preview/review；不重做未变配音/人物；媒体结果变化重跑结果与delivery |
| 配音文本或最终WAV改变 | 新WAV与来源回执，重建受影响口型/声学时轴和下游绑定；不借改字幕掩盖漏念 |
| 本人原片/人物、素材、契约或导演编排改变 | 记录来源与新revision，按真实影响重plan/preview/样段及复核；不消费被否决人物派生 |
| 分块运行中/失败 | 先核本任务进程、manifest、输出和退出态；已有有效块只由现有resume实核续接，未知运行态不复制执行者 |
| 目录刷新失败 | 按PIPELINE的可信旧快照+日期/失败说明处理；无可信快照不定选型，不编fresh |
| 视觉工具/模型额度失败 | 先记录并诊断，按已授权合格通道恢复；已知耗尽不盲试。没有实际动态观察则停受影响定稿/全片render，不拿静帧补签 |
| 相同故障连续两轮 | 停盲重跑，保留最小反例并定位根因；只暂停受影响依赖，既有总预算不重置 |

复用是输入、工具/传递依赖和环境满足现有合同且产物实际一致后的决定，不由同名文件、旧成功状态或单一SHA自动决定。新片不能引用旧片听感/视觉接受；失败、过期、未覆盖的回执不复用为通过。能力样段可同时回答导演风险，仅在满足当前kind=pilot链、真实声音片段和请求绑定时才纳入正式复核，不能省样段自己的登记。

发现影响本期的skills/方法问题立即到真源窄修，先保留失败再验证恢复；对同型问题按合同普查。将同一冻结输入上的修复合为可审批次，正常hook执行规定检查；不额外反复全量跑，也不为快而改hook或绕门。没有真实问题的通用改造不挤占出片主线。

## 留最少但可解释的时间证据

沿用本期qa执行记录，给实际阶段记：stage、started_at、finished_at、输入/输出引用、结果、是否等待或返工、具体原因。时钟现场读取，不用模型估计补历史。原命令已有elapsed就引用，不新造第二个计时服务。

- 总历时：用户本期制作授权/实际开始→渲出、候选交包、工程收尾分别报告；各点来源明确，不把交包时间改成用户接受时间。
- 阶段耗时：并行阶段可以重叠，不能简单累加后称总工时。活动/等待/返工无法区分时写UNKNOWN，不编故障占比。
- 阶段计划耗时仅用于诊断；10—20分钟有界自检看实际产物增量，长任务按DEV_RULES监督与保险丝。超预算调查原因，不能降低推理档、偷偷省门或到时签PASS。
